## 🧭 How I work

- Start with business risk and define observable expected outcomes.
- Test at the right boundary—UI, API, or database—based on what the environment actually supports.
- Check state and invariants, not just success messages.
- Make failures diagnosable with focused assertions, traces, logs, and reports.
- Keep failures, retries, flaky tests, known-defect probes, and skipped tests distinct.

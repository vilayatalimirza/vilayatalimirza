## 🧭 How I work

- Start with business risk and define observable expected outcomes.
- Test at the correct boundary: UI, API, or database, based on what the environment actually supports.
- Verify state and business invariants, not only success messages.
- Make failures diagnosable with focused assertions, traces, logs, and reports.
- Keep first-attempt passes, retries, flaky tests, expected defect probes, failures, and skipped tests distinct.
